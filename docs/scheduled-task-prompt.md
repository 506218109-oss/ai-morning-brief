# 定时任务提示词

在 Claude 桌面 App 里新建一个每天运行的定时任务（比如每天 15:00），把下面这段作为提示词。把 `<项目目录>` 换成你克隆仓库的绝对路径。

权限规则见同目录的 `claude-permissions.example.json`：把里面的规则加进你运行目录下的 `.claude/settings.local.json`（`Edit` 那条的路径按你的目录结构调整）。第一次建好后，建议先手动点一次“立即运行”，把剩下的权限确认一次点完。

```text
这是每天自动运行的无人值守任务：生成当天的中文 AI 日报，发布到 GitHub Pages，并用 Bark 推送到用户手机。

第一步：用 Read 工具完整阅读运行手册 <项目目录>/RUNBOOK.md ，然后严格按它的步骤、选题标准和红线执行。手册是唯一权威说明，里面有全部命令、文件格式和失败时的处理规则。

最重要的一条（否则任务会卡死在等用户点“允许”）：
- 全程只用 `python3 run.py <子命令>` 这一个入口（先 `cd <项目目录>`）。子命令有：status、collect、full、search、fetch、save、build、publish、push、log。它们已被预先授权。
- 命令里不要写日期（脚本自动取当天），不要临时拼 curl、python3 -c、python3 - <<EOF、echo >> 文件、bash 脚本、带管道或重定向的命令。读文件用 Read 工具，改稿子用 Edit 工具改 issues/ 下的文件。
- 某件事用这些子命令做不到，就跳过，并在最后回复里说明缺什么，不要想别的办法绕。

其他要点（细节以手册为准）：
- 先执行 `python3 run.py status`：提示今天已经推送过就直接结束。
- 不要向用户提问；拿不准就按手册规则处理，并在最后回复里如实说明。
- X、微博、知乎只读采集；不打印 Bark 密钥；不编造任何数字、时间、引语或链接；不给投资建议。
- 选题：当天最大的商业/资本市场新闻必须有并放最前；按真实热度排序，不机械去重；每条资讯都要写“对运营/内容人”的影响。
- 写完稿必须逐条回原始数据自查，再 build、publish、push。
- publish 没有输出 "live": true 之前，不要 push --send。
- 出错时把报错原文记下来，重试 1 次，仍失败就停下并如实汇报，不要静默反复重试。

最后用中文回复，不超过 8 行，格式按手册第 7 步：是否已发到手机和链接、今天 3 条重点、采集缺口和需要用户处理的事、自查改了哪几处。
```
